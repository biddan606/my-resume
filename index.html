저는 아래와 같이 실천하고 있습니다

의도 있는 프로그래밍을 지향하며, 프로젝트에 가장 적합한 방식을 분석하고 적용합니다. 명확한 문서화와 소통을 통해 팀원 모두가 같은 방향으로 나아갈 수 있도록 합니다.

의도적인 설계와 개발 코드 작성 전 구현 목표와 방향성을 명확히 설정하고, 의식적인 의사결정을 통해 개발을 진행합니다.
철저한 사전 분석 구현 전 도메인과 요구사항을 깊이 이해하고 분석하여 근본적인 문제 해결 방향을 설정합니다.
효과적인 문서화 API 명세, 아키텍처 설계 문서 등을 통해 개발 의도를 명확히 하고, 팀원 간 일관된 이해를 형성합니다.
상황 맞춤형 접근법 정형화된 best-practice를 무조건 따르기보다, 각 프로젝트의 고유한 맥락과 요구사항에 가장 적합한 해결책을 모색합니다.

보유한 기술 스택입니다

Spring Boot

  • Spring Framework의 내부 동작 방식(Bean 생성 및 등록 과정, AOP Proxy 적용 방식 등)을 이해하고 있어 문제 발생 시 디버깅이 용이합니다.
  • JPA와 Hibernate의 동작 원리(영속성 컨텍스트, 지연 로딩, 캐싱 등)를 이해하여 N+1 문제나 성능 이슈를 효과적으로 해결할 수 있습니다.
  • Spring의 트랜잭션 관리 메커니즘을 이해하고 있어, 적절한 격리 수준과 전파 설정을 통해 데이터 일관성을 보장할 수 있습니다.

Docker

  • 다단계 빌드를 통해 빌드 스테이지와 실행 스테이지를 분리하여 최종 이미지 크기를 최적화할 수 있습니다.
  • 도커 레이어 캐시를 효율적으로 활용하여 빌드 시간을 단축하고, 이미지 재사용성을 향상시킬 수 있습니다.
  • 볼륨 마운트와 네트워크 설정을 통해 개발 환경과 운영 환경의 일관성을 유지할 수 있습니다.

AWS

  • 다양한 배포 방식(EC2, Elastic Beanstalk, Lightsail, ECS)의 경험이 있어, 프로젝트 규모와 요구사항에 따라 적절한 배포 전략을 선택할 수 있습니다.
  • EC2와 RDS의 보안 그룹 설정, IAM 역할 관리를 통해 안전한 인프라 구성이 가능합니다.
  • Auto Scaling의 스케일 업/다운 메커니즘을 이해하고 있어, 인스턴스 준비 시간과 쓰로틀링을 고려한 적절한 스케일링 정책을 설정할 수 있습니다.

프로젝트 개요

코딩테스트 스터디 플랫폼으로 마음이 맞는 스터디원들을 모집하고 Solution 템플릿을 제공합니다. 이를 통해 코딩테스트 리뷰에 있어 체계적인 설명이 가능합니다.
LLM의 등장으로 해결책 자체는 쉽게 얻을 수 있게 되었습니다. 이 점을 고려하여 저희 플랫폼은 단순한 해결책보다 문제 해결 접근 방식과 코드 작성 의도에 초점을 맞춘 스터디 경험을 제공합니다.

주요 구현 사항

  • 도메인 주도 API 설계 및 문서화 시스템 구축 비즈니스 요구사항 정확한 구현과 개발 병렬화
    • 도메인 개념 분석과 모델링을 통한 API 설계 (UI가 아닌 비즈니스 중심)
    • OpenAPI 3.0 표준을 준수한 상세 API 명세 작성 및 유지 관리
    • Docker-compose와 Redoc으로 자동화된 API 문서 배포 시스템 구축
    • 프론트엔드 팀과의 API 계약을 통한 동시 개발로 출시 기간 단축
  • 표준 기반 데이터 교환 프로토콜 설계 리소스 관계 명확화 및 네트워크 요청 최소화
    • JSON:API 표준을 활용한 관계형 리소스의 일관된 표현 방식 구현
    • RFC 9457 ProblemDetail 스펙 기반의 체계적인 오류 처리 시스템 개발
    • 복잡한 리소스 관계를 명확히 표현하고 단일 요청으로 연관 데이터 효율적 조회
    • 리소스 기반 프론트엔드 요청 최적화로 네트워크 트래픽 감소 및 확장성 확보
    • 일관된 오류 응답 형식으로 API 전반에 예측 가능한 오류 처리 및 모니터링 용이
